# SB-CB λ=10、M=4 时延尖峰诊断

## 结论

旧结果中的 22.50 ms 尖峰不是绘图错误，但也不是可信的稳态平均时延。
它来自一个被旧稳定性门槛误判为稳定的拥塞雪崩 run。采用更严格的 5%
速率门槛、1% 删失门槛和 backlog slope 检查，并用 5 个独立评估种子
重跑后，该点只有 2/5 run 稳定，因此应标为混合/不稳定，不能报告有限
稳态均值。

## 旧结果为何被误判

| 指标 | 旧结果 |
|---|---:|
| 最优 q | 0.1 |
| 评估 run 数 | 2 |
| stable_fraction | 1 |
| 平均时延 | 22.501 ms |
| p95 时延 | 271.936 ms |
| 到达率 | 375.5 pkt/s |
| 测量期吞吐 | 362.5 pkt/s |
| backlog slope | +14.361 pkt/s |
| Little 定律相对误差 | 3.633（363.3%） |

两个旧评估 run 中，一个正常（平均时延 1.493 ms），另一个进入拥塞雪崩
（平均时延 43.510 ms、p95 540.318 ms、平均完成包尝试 95.28 次）。
异常 run 在停止到达后的排空期最终清空，所以 `completion_ratio=1`、
`final_backlog=0`。旧 analysis 配置允许 25% 的到达/离开速率误差且不要求
backlog slope，通过了形式上的稳定判定，但其 Little 定律误差已经明确否定
了稳态解释。

异常 run 的诊断计数也显示正反馈失控：

- RTS 尝试 36,314 次，失败 35,049 次；
- RTS 响应超时 33,240 次；
- NAV 失败 20,181 次，保护期违规 27,898 次；
- 数据失败 808 次，数据碰撞 289 次；
- 有害漏检机会 95,251 次。

## 重跑设计与结果

- q 网格：
  `[0.005, 0.0075, 0.01, 0.0125, 0.015, 0.02, 0.025, 0.03, 0.04, 0.05, 0.075, 0.1]`
- 3 个调优种子，2 s 测量；
- 5 个独立评估种子，0.5 s 预热、3 s 测量、3 s 排空；
- 5% 速率门槛、1% 删失门槛、5% backlog slope 门槛。

调优阶段选择 `q=0.03`，但独立评估只有 2/5 run 稳定：

|---:|---:|---:|---:|---:|:---:|
| 1 | 392.67 | 119.67 | 819 | +389.65 | 否 |
| 2 | 411.00 | 0.00 | 1356 | +411.45 | 否 |
| 3 | 400.00 | 400.00 | 0 | +0.09 | 是 |

合并结果为 `stable_fraction=0.4`，稳态平均时延记为 `NaN`。约 4.650 ms
只是不稳定/混合 run 中已完成包的条件均值，不能作为稳态时延。

## 机制解释

这是隐藏节点和固定 p-persistent q 共同形成的双稳态/亚稳态现象：

1. 随机的一组 CCA、ICR 或 NAV 漏检引起并发 RTS 和数据失败；
2. 失败节点重新等待 DIFS 后再次以固定 q 竞争；
3. 队列和活跃 HOL 节点数增加，使同一时刻的尝试数上升；
4. 高漏检率使大量节点在 AP 忙时仍启动 RTS，进一步增加超时和数据干扰；
5. 系统可能回到低积压稳态，也可能进入持续碰撞的拥塞吸收区。

因此，短调优种子恰好全部处于低积压轨道时，会错误地认为 q 很好；独立
评估种子能够暴露雪崩概率。

## 后续建议

当前结果应保留为“不稳定”，不能通过平均已完成包时延消除尖峰。调优数据
显示 `q<=0.015` 的三个调优种子均稳定，其中 `q=0.015` 的调优平均时延约
1.990 ms。若要寻找该点的稳健工作参数，应固定 `q=0.015`，再使用至少
5 个独立评估种子直接验证；在该验证全部稳定前，不应恢复有限稳态时延。
